# 2026-10-22

## Claw-Mesh 同步链路全面修复 (heartbeat 巡检发现)

### 背景
bot2 的两个 4 小时同步任务**从 2026-03-15 起一直全部失败**（日志 5296 条 ERROR），
每次都是"下载 → 合并失败 → 回滚"，实际从未同步成功过。

### 排查过程

| 节点 | 状态 | 问题 |
|------|------|------|
| bot2 | ❌ | cron 同步任务全部失败；只有只读拉取，无回流 |
| bot3 | ❌ | claw-mesh-sync.sh 的 `MACHINE_NAME` 误写为 `bot4`；`WORK_DIR=/tmp/botmem-upload` 不存在；同步 cron 被注释 |
| bot4 | ❌ | `/tmp/botmem-upload/botmem` 内容停留在 2026-05；无同步 cron 实体条目 |
| bot5 | ❌ | 本地 git clone **分叉 65454 个提交**，`git pull --rebase` 从 2026-09-21 起每 5 分钟失败一次 |
| bot6 | ⚠️ | 唯一能正常 push 的节点，但同步 cron 被注释（2026-09-21 停用），靠手动触发 |

### 根因
1. **路径漂移**：bot2 的 `sync-from-slave.sh` / `sync-from-peer.sh` 依赖上游节点的
   `/tmp/botmem-sync/botmem`，但上游已迁移到 `/tmp/botmem-upload/`，且该目录会被清理
   → `远程目录不存在` → 合并失败 → 回滚。
2. **stdout 污染**：`select_sync_node()` 用 `echo "$node"` 返回主机名，但函数内
   `log_info` 用 `tee -a` 把日志写进 stdout，返回变量被污染成整段日志文本
   （日志里可见 `ssh: Could not resolve hostname [2026-10-22`）。
3. **git 仓库污染**：bot5 的 clone 提交了 7.5 万个文件（含 `node_modules`），
   且本地历史与 origin 分叉 65454 个提交 → rebase 永久失败。
4. **凭据失效**：全局 `~/.git-credentials` 里存的 `[已移除]...` token 已失效，
   且配置了 `url.insteadof` 全局改写规则，导致所有 `https://github.com` 克隆
   都自动带上失效 token → `could not read Password` 推送失败。

### 修复动作

**bot2（本机）**
- 新增 `scripts/sync-from-botmem.sh`：绕过 SSH peer 直连，
  `git clone --depth 1` GitHub → 只取 `bot2/memory/*.md` → 合并本地（保留本机 state json）。
  带备份/验证/回滚，支持 `--dry-run` / `--rollback`。
- 新增 `scripts/upload-to-botmem.sh`：补上**回流**链路（本机 memory/ → 仓库 `bot2/`），
  含敏感信息脱敏（[已移除]/[已移除]/ssh 口令）。此前 bot2 是纯只读从节点，
  本机记忆永远无法进集群仓库，`bot2/memory` 停留在 2025-11。
- crontab 重写：
  - `0  */4 * * *` sync-from-botmem.sh（拉取）
  - `30 */4 * * *` upload-to-botmem.sh（上传）
  - 移除失效的 sync-from-slave.sh / sync-from-peer.sh
  - 旧 crontab 备份在 `/tmp/cron.bak`
- 修正 `memory/claw-mesh-state.json`（原有 `errorCount: ,` 是非法 JSON）→ healthy。
- 新增 `.gitignore` 忽略 `memory.backup/` `.openclaw/` `*.log`。
- 清理全局失效凭据：移除 `url.insteadof` 规则，
  `~/.git-credentials` 改为有效 token `[已移除]...`。

**bot5**
- `git branch -f backup-local-diverged HEAD`（保留旧历史备份分支）
- `git fetch origin && git reset --hard origin/main` → 与 origin 对齐。
  验证：`bot5/` 目录内容与 origin/main 仅差两个 state json，无数据丢失。
- 5 分钟 cron 立即恢复，10:15 成功 push（`0488120..f7390ec`）。

**验证**：bot2 → GitHub → bot2 完整往返成功，`memory/2026-10-22.md` 上传后能拉回。

### 遗留
- bot3 的 `claw-mesh-sync.sh` 里 `MACHINE_NAME="bot4"` 是错的，`STATE_FILE` 也指向 bot4 目录；
  bot3 上 `/tmp/botmem-upload` 不存在，同步 cron 被注释。**未改动**（其他机器的既有状态，
  改需要确认）。
- bot4、bot6 的同步 cron 也是注释状态，实际推送目前依赖 bot5（每 5 分钟）+ 偶发手动触发。
- bot3/bot5/bot6 的脚本里硬编码了 GitHub token，虽然上传时有脱敏规则，
  但 token 本身仍是明文躺在远端脚本里。**建议轮换该 token**。
- 仓库里混入了 7.5 万个 `node_modules` 文件（bot5 提交），仓库体积膨胀，
  建议在 `.gitignore` 里排除并做一次 history 清理（需人工决策）。
