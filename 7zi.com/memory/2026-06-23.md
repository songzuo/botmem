
## 10:15 — 重大: 系统时钟漂移导致 bot 僵死 5min
**问题**: 10:07:46 scan 时系统时钟比 binance 快 1.2s,触发 -1021 timestamp 错误
- `get_real_risk_metrics` 失败 → cache fallback
- `binance_scan` 抛 "too many values to unpack (expected 6)" 
- bot 整个 scan cycle 失败,3min 才恢复 (5min sleep 期间)
- 11 个仓位全停,无法开/平仓

**修复**:
1. 手动用 binance 时间 set 修复 (`date -u -s @binance_time`)
2. 配置 /etc/systemd/timesyncd.conf 指向 cn.pool.ntp.org (国内可达)
3. 添加 /etc/cron.d/ntp-sync-safety 每 30min 重新同步 (safety net)

**结果**: 时间差从 +1215ms → +26ms,binary API 正常
- 10:13:48 bot 恢复正常,11 仓位继续运行
- 10:15:48 也是正常 scan

**教训**:
- 国内 VPS 出 UDP/123 受限,默认 ntp.ubuntu.com (IPv6) 不通
- 必须用 cn.pool.ntp.org (国内 Cloudflare)
- 需要永久 cron 守护
- "System clock synchronized: no" 不可靠,以 diff 实测为准

## 长期建议
- 添加 heartbeat 检查:如果 bot 日志 5min 内无新行,自动告警
- 监控 Lev=0 异常 (这是 timestamp 错误表征)
