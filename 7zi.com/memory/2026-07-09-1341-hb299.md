### 🔬 ROOT CAUSE: blacklist bypass (decision_system.save_state clobbers blacklist)
**不是 v3.save_state bug, 是 decision_system.save_state()** clobbers blacklist key 每次 save:

```python
# decision_system.py line 145-156
def save_state(s):
    if os.path.exists(STATE_FILE):
        try:
            with open(STATE_FILE) as f:
                existing = json.load(f)
                for protected_key in ['recent_fills', 'recent_trades_24h']:
                    if protected_key in existing:
                        s[protected_key] = existing[protected_key]
        except: pass
    with open(STATE_FILE, 'w') as f: json.dump(s, f, indent=2)
```

**bug**: `s` 是 decision 的 state object, 没有 `blacklist` key. decision save 时: 读 existing (有 blacklist) → 拉 recent_fills → 写 s (无 blacklist). **blacklist key 每次 decision save 都被 silently drop**.

**时序**:
- v3 cycle N: 检测 SKYAI close → 加 blacklist SKYAI → save_state → state.json 有 SKYAI blacklist
- v3 cycle N+1 到 N+9 (in-memory): SKYAI 还在 blacklist, 安全
- decision save (5min): 读 state.json → 拉 recent_fills → 写回 state.json **无 blacklist**
- v3 cycle N+10 (reload 每 5 cycle): blacklist 被 clobber 为空
- SKYAI signal 来 → v3 不 filter → OPEN

**为什么 LAB 有时 filter 触发**:
- 12:01 LAB blacklist added → 12:01 LAB filter (47h) ✅
- 13:13 LAB blacklist added (after close) → 13:16 LAB filter (47h) ✅ — 时序碰巧
- 13:28 LAB blacklist added → 13:31 LAB filter (47h) ✅ — 时序碰巧
- **关键是 close → 下次 cycle 在 5min 内, blacklist 在内存幸存**

**为什么 SKYAI / EVAA / KORU 全 bypass**:
- SKYAI 12:04 close → 12:16 SKYAI open (12min 后) → 已 clobber
- SKYAI 12:19 close → 12:31 SKYAI open (12min 后) → 已 clobber
- 5 次 SKYAI open 全在 close 后 12-15min, 全 bypass

**fix**: decision_system.save_state 加 `'blacklist'` 到 protected_keys (1 行)
```python
for protected_key in ['recent_fills', 'recent_trades_24h', 'blacklist']:
```
