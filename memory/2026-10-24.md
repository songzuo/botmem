## 🔴 重大发现：脱敏 sed 误伤标识符，17 个脚本变量名被改坏（21:20 发现并修复）

### 触发
跑 `scripts/health-check.sh` 时报：
`line 255: 已移除: syntax error: operand expected (error token is "已移除")`

### 根因
`claw-mesh-sync.sh` 的全仓库脱敏用了这个 pattern：
```bash
sed -i -e 's/gh[p]_[A-Za-z0-9]*/[已移除]/g' \
       -e 's/sk[_]_[A-Za-z0-9]*/[已移除]/g' ...
```
`sk[_]_[A-Za-z0-9]*` 会匹配到 **`di`sk[_]_**`usage` 里的 `sk_` →
`disk_usage` 变成 `di[已移除]`，`task` 变成 `ta[已移除]`，
`docker_disk_usage` → `docker_di[已移除]`。
**而且这些损坏被 commit 进了共享仓库**（bot5 的 `0e84761d38` 同步提交，2026-10-22 11:20）。

### 影响面
全仓库统计损坏标识符出现次数：
| 损坏形式 | 次数 |
|---------|------|
| `ta[已移除]` (task) | 135 |
| `di[已移除]` (disk) | 25 |
| `update_ta[已移除]` | 10 |
| `docker_di[已移除]` | 4 |
| `bot6_ta[已移除]` / `execute_ta[已移除]` / `agent_ta[已移除]` | 7 |
共 **17 个 shell 脚本**被改坏，脚本直接语法错误无法运行。

### ✅ 修复
1. **改正脱敏 pattern**（3 处：live 脚本 + 仓库 deploy 副本）：
   ```bash
   # 旧: s/sk[_]_[A-Za-z0-9]*/[已移除]/g     ← 会误伤 disk_usage / task
   # 新: s/(^|[^A-Za-z0-9_])sk-[A-Za-z0-9_-]{20,}/\1[已移除]/g
   #    s/(^|[^A-Za-z0-9_])gh[p]_[A-Za-z0-9]{20,}/\1[已移除]/g
   ```
   关键点：**用 `sk-` 连字符而非 `sk_`**（OpenAI key 实际格式就是 `sk-`），
   且要求 ≥20 位 + 左侧不是标识符字符。
2. **从父提交恢复 17 个脚本**：`git checkout 0e84761d38^ -- <files>`
3. 恢复后**只单独脱敏密码**（`[已移除]` → `[已移除]`），不碰标识符
4. `bash -n` 全部 17 个脚本语法检查通过
5. 实跑 health-check.sh，确认不再有 `syntax error` / `integer expression expected`（已移除）
6. 同步修好 `grep -rlE` 的文件定位 pattern（原来 `sk[_]_[A-Za-z0-9]{20,}` 找不到真 token）
7. 已推送：`0dc95dcc1b`
