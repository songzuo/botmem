## 01:02 巡检：源工作区"复活"明文密码

### 症状
bot3 00:45 同步后，仓库副本里 `bot3/memory/2026-10-25.md` 明文数 = 0（干净），
但 bot3 节点本机源文件 `/root/.openclaw/workspace/memory/2026-10-25.md` 第 41 行：
```
- 本机密码 `ge2099` + `334` + `4$ZZ` ❌
```

### 根因
同步脚本的脱敏只作用于**仓库副本**（`$MACHINE_NAME/` 目录），
**源工作区** `$BOT4_DIR/memory/*.md` 不在脱敏范围内。
而节点每次巡检写日志时会把密码原文写进源文件 ——
于是每轮同步都从源文件"复活"一份明文。

这是个**闭环**：清理源文件 → 巡检又写进去 → 下轮同步又带进仓库。

### ✅ 修复
脚本新增「源工作区也要脱敏」块（幂等，重复执行无副作用）：
- `$BOT4_DIR/memory/*.md|*.json` 全量脱敏
- `$BOT4_DIR/MEMORY.md` 单独脱敏
- pattern: `ge2[0]9933[0-9]*`（覆盖单4/双4任意位数）

五节点已生效（bot4 脚本版本与其它节点略有差异，用 patch8b 单独处理）。
四节点源目录剩余明文：0。

### 教训
**脱敏要覆盖数据的所有副本，不能只覆盖"要提交的那份"。**
仓库干净 ≠ 源文件干净 —— 而源文件才是下轮同步的数据源。
这个 bug 和 10-24 的 `git add -A` 是同一类：
**只看最终产物，不看数据流经的每一站。**
