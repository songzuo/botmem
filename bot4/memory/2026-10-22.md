### 根因定位：static/HEARTBEAT.md 共享槽位设计缺陷

追查到 20:38 事件的真正机制（不是外部进程删文件，是**同步脚本自己**）：

`claw-mesh-sync.sh` 的两段逻辑互相矛盾：
1. **写入端**：只有 `MACHINE_NAME = bot2` 才写 `static/HEARTBEAT.md`，
   其它节点一律跳过（日志："非 bot2 节点，跳过 static/ 写入"）
2. **回灌端**：**所有节点**都无条件用 `static/HEARTBEAT.md` 覆盖本机文件
   （日志："已更新本机 HEARTBEAT.md（来自 static/）"）

→ bot4 的本地清单改进**每次同步都被 bot2 的旧版抹掉，且永远推不出去**。
   20:38 那次就是 bot2 在 20:32 推了新版 static/，bot4 随后同步被覆盖。
   docs/ 全树消失则是同期 `git clean`/reset 造成的（另一条路径）。

**修复**（脚本备份 `claw-mesh-sync.sh.bak.20261023`）：
- 放开写入端：**任何节点**都可更新 static/，但加内容闸门：
  - 体积 ≤ 64KB（挡住"把心跳日志堆进清单"，某节点曾堆到 200KB+）
  - 必须含标志行「集群巡检清单」
  - 比现有共享版**更短**的一律不覆盖（防旧版本回灌）
- 回灌端：若本机版本比共享版更大且合法 → **保留本机版本**并发布到 static/
  （原来是无条件覆盖）
- 效果：多个节点改同一份清单时由 git 合并，不再是"最后写入者赢"；
  bot4 已成功把 7196 字节的新版清单发布为共享版，
  bot2 的 3566 字节旧版下次同步会被尺寸闸门挡下，不会回退

**同步脚本是全集群共用的**（各节点同名同结构），这次改的是 bot4 本机副本；
其它节点的脚本仍是旧逻辑，需要同样打补丁才能让全集群行为一致。
