## 11:02 巡检 + 修复 08:15 高频上传失败导致的数据丢失

### 发现
`/var/log/botmem-upload.log` 显示 **08:15 那轮高频上传失败**：
`fetch first` → `non-fast-forward` → `non-fast-forward`，三次全败，
**bot4 那一轮的 memory 没进远端**（`git log -- bot4` 里 08:15 之后没有对应提交）。
此前 04:15/00:15 等都成功，所以是偶发但会丢数据。

### 根因
1. `git fetch origin ... || true` 把**网络失败吞掉**，
   接着 `git reset --hard origin/main` 用的是**过期**的 origin/main；
2. `git checkout -B main origin/main` **无条件**把分支指针拽回远端，
   即使 rebase 成功，本地提交也被抹掉；
3. 重试只有 3 次，敌不过并发写入方（bot5 每 5 分钟 + bot2 + 7zi backup）。

### 已修（upload-botmem.sh + upload-botmem-daily.sh）
- fetch 必须成功才继续，失败等 15 秒重试，**绝不 reset**
- 只有 `git symbolic-ref HEAD` 失败才重建分支指针
- rebase 冲突才放弃本地提交，且**必须重新复制文件再提交**
- 重试 3 → 8 次
- 顺带把两个脚本的脱敏 sed 换成左边界 pattern（与 claw-mesh-sync.sh 一致）

### 验证
- `upload-botmem.sh` 手动跑 → `03ce254765` 推送成功，远端 `bot4/memory/2026-10-24.md` 已含 11:05 前的全部记录 ✅
