## 关键设计决策（来自 v1.1.0_ARCHITECTURE.md）

### 1. 缓存策略

#### L1 缓存（内存）
- **用途**: 会话、权限、配置
- **TTL**: 5-30 分钟
- **实现**: JavaScript Map + LRU 淘汰策略
- **最大条目数**: 1000

#### L2 缓存（Redis）
- **用途**: 列表、统计、未读数
- **TTL**: 2-15 分钟
- **缓存键命名**: `{service}:{entity}:{id}:{version}`
- **保护机制**:
  - 缓存穿透：空值缓存
  - 缓存雪崩：随机 TTL 偏移
  - 缓存击穿：互斥锁（可选）

### 2. 消息队列选型

#### 技术选型：Bull (基于 Redis)
- **原因**:
  - 成熟稳定，社区活跃
  - 与 Redis 已有基础设施兼容
  - 支持优先级、延迟任务、重试机制
  - 内置 Web UI 监控

#### 队列配置
```typescript
// 邮件队列：3 次重试，指数退避
email: {
  attempts: 3,
  backoff: { type: 'exponential', delay: 2000 }
}

// 通知队列：3 次重试，快速重试
notification: {
  attempts: 3,
  backoff: { type: 'exponential', delay: 1000 }
}

// 分析队列：2 次重试，慢速重试
analytics: {
  attempts: 2,
  backoff: { type: 'exponential', delay: 5000 }
}
```

### 3. 数据库分片准备

#### v1.1.0 策略（准备阶段）
- 添加 `shard_key` 字段到所有核心表
- 创建 `schema_version` 表追踪数据库版本
- 规范化表命名和索引设计
- 保持单库，为未来分片做准备

#### v1.3.0+ 策略（完全分片）
- **分库策略**: 按业务模块分库
  - `users_db` - 用户库
  - `notifications_db` - 通知库
  - `projects_db` - 项目库
  - `analytics_db` - 分析库
- **分表策略**: 按用户 ID 哈希分表（10 个分表）

### 4. API 版本管理

#### 版本命名空间
- v1.1.0 新功能：`/api/v1/*`
- 旧 API：继续可用（`/api/*`）
- 废弃策略：通过响应头标记废弃 API

#### 统一响应格式
```typescript
// 成功
{ success: true, data: {...}, meta: {...} }

// 错误
{ success: false, error: {...}, meta: {...} }
```

### 5. 安全措施

#### 限流策略（基于 Redis）
- 登录尝试：5 次/15 分钟，封禁 30 分钟
- 密码重置：3 次/小时，封禁 1 小时
- API 通用限流：100 次/分钟，封禁 5 分钟

#### 登录异常检测
- 异常地理位置检测
- 异常设备检测
- 异常时间检测（凌晨 2-5 点）

### 1. 缓存策略

- TTL: 2-15 分钟

### 2. 消息队列

**技术选型**: Bull (基于 Redis)

**队列类型**:
- 任务队列: 异步任务处理
- 优先队列: 按优先级处理
- 延迟队列: 定时任务

### 4. 认证方式

- JWT: 主要认证方式
- OAuth 2.0: 第三方登录
- 2FA: 双因素认证（TOTP）
- SAML 2.0: 可选（企业 SSO）
