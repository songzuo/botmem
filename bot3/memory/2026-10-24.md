## 10:05-10:12 巡检：修复 bot4 detached HEAD 导致推送永久被拒

### 症状
- bot4 08:10 同步失败：`推送被拒` × 6 次 → `❌ Claw-Mesh 同步失败`
- 06:00 之后仓库 tip 停在 `3f9516b3f8`（bot5 的），bot4 再没推成功过

### 根因
`/tmp/botmem-upload/botmem` 的 HEAD 处于 **detached 状态**（`HEAD detached from 9df8224ade`）。
reflog 证据：
```
HEAD@{08:15:08}: rebase (start): checkout origin/main   ← rebase 后留在 detached
HEAD@{05:52:30}: checkout: moving from main to origin/main
```
后果：`git reset --hard origin/main` 在 detached HEAD 下只移动 HEAD 指针，
**不会更新 refs/heads/main** → `git push origin main` 推的是陈旧的本地 main 分支
→ 远端已前进 → 永远 `fetch first` 被拒。
（这就是为什么重试加到 6 次也没用 —— 问题不在重试次数，在分支状态。）

### 修复
四节点 `claw-mesh-sync.sh` + bot4 `upload-botmem.sh` 注入：
```bash
# CLAWMESH_FIX_BRANCH: 确保在 main 分支上，不能是 detached HEAD
git checkout -B main origin/main 2>/dev/null || git checkout main 2>/dev/null || true
```
- 备份 `.bak.20261024*` 已留，语法校验全过
- bot4 手动补跑 → 10:09:39 同步成功，提交 `67b6df32ce` 已进远端
- 四节点 clone 现已全部回到 `## main...origin/main`

### 教训
「push 被拒就加重试次数」是治标不治本。要先确认本地 HEAD 到底在哪个分支上：
`git status -sb` 看是否 `## HEAD (no branch)`。
